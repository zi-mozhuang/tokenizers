## ClassSplit 能否改用现有 `Split`（源码核实完成，待用户决策）

- 结论：**可以**。单 `Split` 节点（`SplitPattern::Regex` + `MergedWithNext` + `invert:false`）即可复现 ClassSplit
  主体语义，ClassSplit 整块可省；`SentenceSplit` 仍是唯一需要新增的模块。
- 机制（`normalizer.rs:745-766` 的反向 fold + `pattern.rs:63-83` 的 run 切分）：
  - 匹配 run → 切点落在 match 起点，**match 与其后内容同段**（朝后粘）；
  - 未匹配 gap run → 被紧邻其**前**的 match 吸收（朝前粘）→ 免费得到"标点/组合符/emoji 附着前段"；
  - 相邻 match 各自成段（`pattern.rs:72` 只在不连续时补 gap run）；首尾零长 gap 不产出空段。
- 推荐 pattern：`\p{White_Space}*(?:[\p{Han}\p{Hiragana}\p{Katakana}\u30FC]+|[\p{Latin}]+|\p{N}+(?:[.,]\p{N}+)*)`
  （`[.,]` 分支用于复刻"数字内部连续"；**不可**用 `\p{L}` 兜底，会把汉字吞进拉丁 run）。
- 4 处偏差：①Common 在 run 中部会触发切分（`他说：你好`→`["他说：","你好"]`，可用 composite 分支闭合：
  `CLASS+(?:[^\p{White_Space}\p{L}\p{N}]*CLASS+)*`）；②末尾空白自动并回前段；③"空白+emoji"方向反转；
  ④白名单外的脚本互不切分。
- **意外收获**：②使 v4 §5.3 的三方冲突自动消失，端到端得到标准 SB11 形态 `["段一。\n","\n","段二。"]`，
  那个默认关闭的开关可删。
- 风险：`\p{...}` 在本仓 Rust 源码中零使用先例（grep 无命中）；`SysRegex` 默认 `onig`
  （`Cargo.toml:106` default features），wasm 走 `fancy-regex`（`unstable_wasm`）→ 属性表可能不一致，需两端实测。
- 状态：**已决策**。用户选「改成单 Split 纯配置」，`design/uax29-sentence-pretokenizer.md` 已重写为 **v5**：
  管线 = `Sequence([SentenceSplit(), Split(CLASS_REGEX, MergedWithNext)])`，ClassSplit 不实现；
  唯一新增模块是 `SentenceSplit`；`fixed_script` 可见性改动随 ClassSplit 一并撤销。
- v5 正文采用的完整正则为 **composite 变体**（`X_SC = S+(?:JUNK*S+)*`，`JUNK = [^\p{WS}\p{L}\p{N}]`），
  它闭合了 v4 偏差①的两种典型情形（`他说：你好`、`cafe\u{0301}bar`）；残余偏差为
  ②末尾空白并回前段（= 标准 SB11 形态，v4 §5.3 冲突消失）、③空白+emoji 方向、④脚本白名单。
